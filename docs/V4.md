# v4: fresh bot (branch `v4-fresh`, folder `v4/`)

Written from scratch on Oct 4. v3.5 (`macpoker-scaffold/`) was used only as a reference opponent.

## How it plays

- **Preflop** (`foldv4.Brain.preflop`): percentile ranges from `pf_table.py` (169 hand classes ranked by
  equity vs 1 and 3 random hands). Opens tighten with more players behind. Calls and 3-bets scale with the
  raiser's observed opening rate and the raise size. Big raises and jams are called by where our hand sits
  in that raiser's range.
- **Postflop** (`foldv4.Brain.postflop`): an expected-value engine.
  1. Each opponent's range (1,326 combos) is rebuilt from this hand's actions. Every action multiplies a combo's
     weight by how often the **real ladder field** takes that action with that hand class, in that spot and at
     that bet size (`field_model.py`, fitted from scraped games). Weights are tempered by the opponent's own
     looseness and aggression in this game.
  2. One Monte Carlo sample set gives our equity against those ranges, and is reweighted for every scenario.
  3. Check, call, fold and each bet size are scored in chips. The field's fold/call/raise rates per hand class
     predict how each opponent answers each size, scaled by that opponent's own fold rate.
  4. Guards: no shove above 1.6x pot; a bluff must beat checking by 10% of the pot; calls of pot-size or bigger
     bets need a 4%-of-pot margin.
- About 15-70 ms per decision and about 4 s per 100-hand game. Every hook is wrapped, so the fallback is
  check/fold.

## Rebuilding the data

```bash
python tools/scrape_ladder.py          # fresh games into games/
python tools/v4/fit.py                 # -> v4/field_model.py + opponents/clone_data.json
python tools/v4/make_preflop.py        # -> v4/pf_table.py (only if the evaluator changes)
```

## Testing

- `tools/v4/arena.py A/main.py B/main.py --tables 60`: 5-seat tournament tables. The other 4 seats are
  **behavioural clones of real ladder bots** (`opponents/clone.py`: each bot's own action frequencies per spot,
  fitted from its ladder games). Each table is a full duplicate set, and placement points are scored like the
  tournament. `--pool file:tag,house:call,...` uses hand-written bots instead.
- `tools/v4/river_check.py A/main.py B/main.py` (and `STREET=turn` / `STREET=flop`): puts the build in every
  real heads-up spot where a bot faced a bet, with the exact message stream that bot saw, and scores call/fold
  against the bettor's **real cards**.

## Open lead

Preflop shove calls use the raiser's overall preflop raise rate as their range width. Some bots raise a lot but
shove narrow: the GOON raises 23% of hands, but half its big raises are top-7% hands. orcabot is the opposite
(half its big raises are worse than the top 26%). Tracking each bot's big-raise frequency separately should call
shoves more accurately. This is untested.

## Review after the lock: us vs the top bots (389 ladder games, Oct 4 18:00)

`python tools/v4/field_report.py` ranks every bot by **luck-adjusted** chips/game (all-ins before the river
replaced by equity) and splits results into showdown / no-showdown / preflop.

| | luck-adj/game | showdown chips | won at showdown | VPIP | aggression | fold to bet |
|---|---|---|---|---|---|---|
| Top 6 by luck-adjusted (sawit-bot, Gladiators, Sus bot, yep, tungbot, catherine) | +77 to +128 | +63 to +140 | 51-60% | 18-31% | 1.9-3.8 | 45-59% |
| v3.5 (53 games) | +36 | +78 | 47% | 18% | 2.8 | 51% |
| v4.x (19 games) | +27 | -5 | 49% | 15% | 3.5 | 41% |

v3.5 and v4 are equal within noise. Both sit around 15th-20th of 47. The gap to the top is **showdown value**: the top
bots win +94 to +140 per game at showdown, while we win +56 to +78 (and v4 has only 19 noisy games).

**Clearest single finding, v4 turn/river bet sizing by hand type (opening bets):**

| | two pair+ | one pair | air/draw |
|---|---|---|---|
| Top bots, median size | 0.85x pot | **0.64x pot** | 0.57x pot |
| v4, median size | 1.30x pot | **1.30x pot** (80% of them pot or bigger) | 0.89x pot |

v4 overbets one pair. That folds out worse hands and gets called by better ones. Several of v4's biggest live losses
were exactly this (A-7 / A-J / second pair, pot-size or bigger bets into a better hand). Cause: the response model
groups all "top pair" hands together, so it cannot see that the hands calling a big bet out-kick us.

### What to try next, in order

1. **Size one-pair value bets like the top bots (0.5-0.75x pot)**, and keep overbets for two pair+ and bluffs. Either
   cap the sizes, or split bucket 4 by kicker so the response model sees who calls a big bet.
2. **Call shoves by each bot's real shove range** (track big preflop raises separately from all raises; see Open lead).
3. **Play more hands preflop, mainly late-position opens and 3-bets.** Top bots play 22-25% of hands and 3-bet 6-15%;
   we play 15-18% and 3-bet 4-5%. Our two local tests of looser preflop were neutral, so test this on real-hand
   replays rather than clones.
4. **A better test bed.** The clones copy frequencies only, so they cannot show kicker problems or line-dependent
   strength. Extend the real-spot checks (`river_check.py`) to our own bets: score bet size vs the real caller's cards.
